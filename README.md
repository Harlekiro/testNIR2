# mixuse — сравнение сочетаний функций на территории

Программа для метода НИР «смешанное использование территорий». Территория меняет назначение;
программа показывает, как каждый вариант сочетания функций (Ж, К, ОД, П) скажется на окружающих
кварталах. **Сводного балла и «лучшего варианта» нет** — выбор делает человек.

**Градостроителю — [инструкция пользователя](docs/инструкция_пользователя.md):** где взять программу, какие слои
собрать, как заполнить анкету ноутбука `метод_сравнения_вариантов.ipynb`. Устанавливать пакет через командную строку
не нужно: ноутбук находит папку `mixuse` рядом с собой и сам ставит недостающие библиотеки; без Anaconda —
`установить.bat` (один щелчок). Точный расчёт школ и садов — `подготовить_город.bat` (один раз на город).

## Установка (для командной строки и тестов)

Нужен Python 3.10+ и пакеты numpy, pandas, matplotlib, pyyaml, pytest:

```
pip install -r requirements.txt
```

Геометрия написана на numpy, без geopandas и shapely — ставить ГИС-библиотеки не нужно.

## Как посчитать свои данные

1. Положите слои в одну папку (GeoJSON или GeoPackage):
   - **кварталы** — полигоны (номер квартала — по желанию);
   - **здания** — полигоны с полями: жилое (1/0), этажность, площадь застройки, жилая площадь, жители
     (последние три могут отсутствовать — программа оценит их и напишет об этом в отчёте);
   - **сервисы** — папка «один файл = один тип сервиса» (тип — имя файла: `cafe.geojson`, `school.geojson`…);
     у школ и садов — поле `capacity` (число мест);
   - **зоны** — обязательно: полигоны землепользования (ПЗЗ или функциональные зоны генплана) с кодом зоны
     или поле зоны в слое кварталов. Без зон расчёт не идёт: программа не отличит производственные
     и общественно-деловые кварталы.

   Все слои набора — в одной системе координат: EPSG:4326 (градусы) или метрической (UTM, МСК).
   Смешение систем — ошибка проверки (правило 4.1.2). EPSG:3857 не принимается — в нём искажены
   площади и расстояния.

2. Составьте файл настроек — программа сделает черновик сама:
   ```
   python -m mixuse init путь/к/папке --name mycity
   ```
   Откройте `configs/mycity.yaml` и проверьте строки с пометкой «ПРОВЕРЬТЕ»: какие поля что значат.
   Сопоставлять коды зон вручную не нужно: программа распознаёт их по словарю **`zone_dictionary.csv`**
   (столбцы «значение; группа; схема; сравнение»): коды ПЗЗ Санкт-Петербурга (`ТП…` → П, `ТД…` → ОД), ПЗЗ других
   городов (`П-…`, `О-…`), функциональные зоны генплана (`Производственная`, `Промышленная`,
   `Коммунально-складская` → П; `Общественно-деловая` → ОД), blocksnet (`LandUse.INDUSTRIAL`, `LandUse.BUSINESS`)
   и OpenStreetMap `landuse` (`industrial`; `commercial`, `retail`). Коды ПЗЗ сравниваются по началу строки,
   слова — по вхождению, без учёта регистра. Черновик настроек показывает рядом с каждым кодом зоны, к какой
   группе его отнёс словарь (X — прочее). Если ваш код не распознан или распознан не так — допишите строку
   в `zone_dictionary.csv` или задайте поправку `zone_rules` («код начинается с …» → группа): она важнее словаря.
   Код, который подходит и под П, и под ОД, — предупреждение; принимается П.
   КИТ варианта впишите в `params`: `kit` и `kit_source` (из ПЗЗ) или `kit_sp_row` (строка табл. Б.1 СП 42.13330.2016).

3. Проверьте данные:
   ```
   python -m mixuse check configs/mycity.yaml
   ```
   Программа перечислит ошибки (расчёт невозможен) и предупреждения (что принято по умолчанию),
   а затем составит **отчёт о данных** (`results/<код>_отчёт_о_данных.txt`): как распознаны коды зон
   (код → группа, кварталов, по какой строке словаря) и какие не распознаны, здания без этажности —
   жилые и нежилые отдельно, жилые дома без числа жителей, школы и сады без числа мест, точки
   предприятий в контурах зданий, производственные кварталы без точек предприятий — и подскажет,
   что дополнить в данных.

4. Посчитайте таблицу кварталов и найдите номера кварталов территории:
   ```
   python -m mixuse blocks configs/mycity.yaml
   ```
   Откройте `results/mycity_кварталы.geojson` в QGIS — номер квартала в поле `block_id`.

5. Сравните варианты (а для перебора всех сочетаний долей — `python -m mixuse explore configs/mycity.yaml`):
   ```
   python -m mixuse compare configs/mycity.yaml --territory 12,13
   ```
   (или впишите `territory: [12, 13]` в настройки).

## Кто что делает

| Кто | Что | Как |
|---|---|---|
| **Подготовщик данных** (один раз на город) | матрица доступности, обеспеченность школами и садами «как есть», файл для страницы | `подготовить_город.bat configs\<код>.yaml` — сам ставит Python 3.11 и blocksnet, ждёт сервер OpenStreetMap, сохраняет всё в `data/<код>/access/` |
| **Градостроитель** | сравнение вариантов, перебор, карта | ноутбук `метод_сравнения_вариантов.ipynb`, команды `compare` / `explore` или страница `страница/конструктор.html` (без установки) |

Школы и сады в вариантах программа считает сама, без участия пользователя (`mixuse/bn_bridge.py`):
1. blocksnet установлен в этом Python — точный расчёт;
2. есть окружение с blocksnet (`%USERPROFILE%\venvs\blocksnet311` или `MIXUSE_BLOCKSNET_PYTHON`) — точный расчёт там, результат возвращается сам;
3. есть сохранённый точный расчёт «как есть» — **оценка**: жители территории уезжают, учреждения территории закрываются; места распределяются по очереди по весу «дети квартала ÷ (время + 1)», как в целевой функции blocksnet; кому учреждение в пределах порога, тот получает место раньше; вытесненные ищут снова;
4. иначе — запасной расчёт 4.7.3.

**Страница** `страница/конструктор.html` показывает сравнение стандартного набора или двух эмпирических и пяти экспериментальных сценариев, карту и экспорт CSV, GeoJSON и PNG. Откройте готовый пример или загрузите `results/<код>_для_страницы.json` (команда `python -m mixuse page configs/<код>.yaml`; для большого города можно задать `--clip 6500`). Школы и сады на странице рассчитываются в оценочном или резервном режиме. [Запуск конструктора и порядок эксперимента](docs/инструкция_пользователя.md#эксперимент-в-конструкторе).

Готовые полные JSON для кнопки «Загрузить JSON» лежат в [`results/для_конструктора`](results/для_конструктора). Слои с рабочими местами по сценариям для QGIS лежат в [`results/employment_layers`](results/employment_layers), пересчитанные итоги и чувствительность к радиусу — в [`results/employment_audit`](results/employment_audit).

Доступ к К и ОД можно считать по готовой пешеходной матрице OpenStreetMap. Для Python укажите `compare --walk-minutes 10`, а в конструкторе выберите «По пешеходной сети». Граница окружения и близость к производству сохраняют геометрические радиусы. [Подготовка матрицы и JSON](docs/инструкция_пользователя.md#доступ-к-к-и-од-по-пешеходной-сети).

## Как blocksnet считает обеспеченность (ТЗ 12.2)

Используется `competitive_provision` blocksnet 1.0.0.dev1 без изменений:
1. **Спрос квартала** = жители ÷ 1000 × норма (школы — 120, сады — 61 место на 1 000 жителей), округлённо до целых детей.
2. **Свои места.** Сначала квартал отдаёт места своих учреждений своим детям — сколько хватает.
3. **Распределение остальных детей.** Программа решает задачу целочисленной оптимизации: выбирает число детей xᵢⱼ из
   квартала i в учреждения квартала j так, чтобы была наибольшей сумма Σ xᵢⱼ · (спросᵢ × местаⱼ) ÷ (времяᵢⱼ + 1);
   из квартала уходит не больше детей, чем у него осталось без места, в учреждение — не больше его свободных мест;
   ребёнка можно направить только в учреждение не дальше k × порога (школы — 15 мин, сады — 7 мин пешком).
   Охотнее заполняются пары «большой спрос — вместительное учреждение — близко».
4. **max_depth** — сколько раз повторить шаг 3, расширяя зону поиска: на k-м повторе допускаются учреждения до
   k × порога. В методе max_depth = 2: место за порогом (до двойного порога) — «получил место, но далеко».
5. **Результат:** обеспеченность в пределах доступности = дети, получившие место не дальше порога ÷ весь спрос
   (основная); «получили место вообще» = (в пределах + за порогом) ÷ весь спрос (подробная таблица).
Учреждениям без числа мест подставляется наименьшая вместимость каталога blocksnet (школа 250, сад 80).
Проверка 12.8: обеспеченность в пределах доступности не больше min(100 %; места ÷ спрос). В Петербурге мест
в школах по данным 451 935 (с подставленными — 488 935) при потребности по норме 645 834: это ограничение данных,
а не результат варианта.

### Рабочие места в сценариях

По умолчанию `jobs_method: local` оценивает J по кварталам-аналогам. Для торговли и услуг (К),
общественно-деловой функции (ОД) и производства (П) программа отдельно считает рабочие места на м² земли
кварталов, где эта функция представлена в оценке занятости. Рабочие места встроенных помещений относятся к их
функциям. Отдельные социальные объекты учитываются в исходной занятости, но исключаются из калибровки К, ОД и П.

Окружение задаёт радиус R. Территория проекта исключена из аналогов. Плотность по остальной части набора
имеет вес одного квартала средней площади местных аналогов. Если местных аналогов нет, используется плотность
остальной части набора. Если аналогов нет нигде, вклад функции показан только во вместимости и выводится предупреждение.

Для каждой функции программа умножает меньшую из двух плотностей, наблюдаемую и КИТ / a, на площадь территории
и долю функции в сценарии. В подробной таблице отдельно показана вместимость проектной площади при полном
использовании, Σ(F × δ / a). Режим `jobs_method: legacy` выводит эту вместимость как J для воспроизведения прежних расчётов.
ΔJ = J − J₀ показывает условное изменение при полной замене застройки. Данные об арендаторах, спросе и переводе
рабочих мест из других районов в формулу не входят.

## Устройство

```
mixuse/
  geometry.py     чтение слоёв, проекция, площадь, точка в полигоне, расстояния
  groups.py       таблица групп сервисов, словарь зон, группа нежилого здания
  blocks.py       шаги 1–4: таблица кварталов, встроенные помещения
  compare.py      шаги 5–6: окружение и показатели
  scenarios.py    варианты
  checks.py       проверка данных; шаги 7 и 7б
  export.py       CSV, GeoJSON для QGIS, JSON для страницы, карта
  config.py       файл настроек YAML
  init_config.py  черновик настроек по папке с данными
  notebook.py     анкета ноутбука → настройки пакета; печать проверки данных
  data_report.py  отчёт о данных (этап 3): только счётчики, без формул
  buildings.py    здания: шаги 1–8 таблицы 4.4 (категории А / Б / В), встроенные помещения по норме типа
  provision_bn.py обеспеченность школами и садами через blocksnet, матрица доступности (раздел 12)
  provision_estimate.py  оценка обеспеченности без blocksnet (по сохранённому точному расчёту «как есть»)
  bn_bridge.py    выбор расчёта школ и садов: blocksnet здесь → окружение с blocksnet → оценка → запасной 4.7.3
  cli.py          командная строка
  params.py       параметры и варианты по умолчанию — в одном месте
configs/          spb_full.yaml, gatchina_layers.yaml, vysotsk.yaml — настройки трёх наборов

метод_сравнения_вариантов.ipynb  рабочий ноутбук: анкета и шаги 0–10, расчёт — функциями пакета
```

## Матрица доступности (точный расчёт школ и садов)

Матрица — время в пути пешком, мин, между всеми парами кварталов набора; по ней blocksnet считает обеспеченность
школами и садами (раздел 12). Хранится в `data/<код>/access/matrix_walk.npz` (numpy, без pickle: при чтении файл не
может выполнить код) вместе с описанием `matrix_walk.json` — версия blocksnet, граф, число кварталов, контрольная
сумма слоя кварталов. При загрузке программа проверяет, что матрица построена на тех же кварталах; если слой
кварталов изменился — просит построить её заново.

Как получить матрицу (один раз на город и заново — если изменился слой кварталов):
- **одним щелчком:** `подготовить_город.bat configs\<код>.yaml` — ставит Python 3.11 и blocksnet
  (`%USERPROFILE%\venvs\blocksnet311`), строит граф и матрицу, считает обеспеченность «как есть»;
- **командой** в окружении с blocksnet (Python 3.11):
  ```
  python -m mixuse osm-download --config configs/<код>.yaml   # файл региона OpenStreetMap в data/osm/ (если его нет)
  python -m mixuse access configs/<код>.yaml                  # граф и матрица → data/<код>/access/matrix_walk.npz
  python -m mixuse provision configs/<код>.yaml               # обеспеченность «как есть» → provision_walk.json
  ```
  Граф берётся из файла OpenStreetMap в `data/osm/` (`--osm-file путь`; `--osm-file нет` — с сервера Overpass).
  Время: Высоцк и Гатчина — 2–3 мин, Петербург — около 25 мин и 5 ГБ памяти.

Для Высоцка и Гатчины матрицы лежат в репозитории; матрица Петербурга (134 МБ) — нет.

Тесты: `python -m pytest tests`.
