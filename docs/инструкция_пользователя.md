# Как посчитать свой город

Инструкция для градостроителя. Программирование не нужно: данные готовятся в QGIS, расчёт запускается в одном ноутбуке.

**Что получится.** Для выбранной территории (кварталы, которые меняют назначение) программа сравнивает пять вариантов сочетания функций — жильё, торговля и услуги, общественно-деловая функция, производство — и показывает для каждого: сколько появится жителей и рабочих мест, как изменится число рабочих мест на жителя в окружении, кто получит или потеряет доступ к функциям, хватит ли мест в школах и детских садах. Лучший вариант программа не выбирает.

---

## 0. Где взять программу

Программа доступна в [репозитории testNIR2](https://github.com/Harlekiro/testNIR2).

1. Скачайте репозиторий: на странице GitHub кнопка **Code → Download ZIP**, затем распакуйте архив. Если умеете работать с git — `git clone <адрес>`.
2. В распакованной папке есть всё нужное: ноутбук `метод_сравнения_вариантов.ipynb`, таблица `таблица_групп_сервисов.csv`, папка программы `mixuse`, эта инструкция в папке `docs`.
3. Подготовка компьютера (один раз). Нужен Python 3.10 или новее; проще всего — Anaconda (anaconda.com). Сам пакет `mixuse` устанавливать не нужно: ноутбук находит папку `mixuse` рядом с собой.
   - **Anaconda или VS Code с Python:** откройте ноутбук из распакованной папки. Первая ячейка ноутбука («Подготовка») найдёт программу и, если каких-то библиотек нет (numpy, pandas, matplotlib, pyyaml), поставит их сама.
   - **Python без Jupyter (Windows):** дважды щёлкните `установить.bat` в распакованной папке — он поставит библиотеки и Jupyter и откроет ноутбук в браузере. В следующий раз запускайте его же.
   - **Google Colab:** загрузите в Colab только файл ноутбука («Файл» → «Загрузить блокнот») и выполните первую ячейку — она скачает программу с GitHub в папку `mixuse_программа`. Свои слои загрузите в `mixuse_программа/data/<имя города>/` (панель «Файлы» слева), затем выполните все ячейки.

Свои слои кладите в папку `data/<имя города>/` внутри этой же папки.

## 1. Какие слои собрать

Формат — GeoJSON (`.geojson`) или GeoPackage (`.gpkg`). **Все слои — в одной системе координат**: EPSG:4326 (градусы) или метрической (UTM, МСК). Web Mercator (EPSG:3857) не подходит.

### Обязательные

| Слой | Геометрия | Поля | Зачем |
|---|---|---|---|
| **Кварталы** | полигоны | номер квартала (можно без него — пронумеруются по порядку) | единица расчёта; границы — по красным линиям или осям улиц |
| **Здания** | полигоны | жилое или нет (1/0, да/нет); **этажность**; желательно — жители, жилая площадь, площадь застройки | поэтажная площадь, жители, рабочие места |
| **Сервисы** | точки или полигоны | тип объекта; у школ и детских садов — **число мест** | функции кварталов, рабочие места, школы и сады |

### Зоны: что с ними делает программа

Слой зон — обязательный: функциональные или территориальные зоны (ПЗЗ, генплан, землепользование), отдельным слоем или полем в слое кварталов. Пример — `functional_zones.geojson` в данных Санкт-Петербурга, поле `functional_zone`.

Сопоставлять коды с ПЗЗ вручную не нужно. Программа:
1. находит все коды в указанном поле;
2. сама относит их к группам по словарю: «ТП», «П-», «Производственная», `INDUSTRIAL`, `industrial` → **производственная**; «ТД», «О-», «Общественно-деловая», `BUSINESS`, `commercial`, `retail` → **общественно-деловая**; остальные → прочие;
3. показывает в проверке данных таблицу «код → группа, кварталов» и отдельно коды, которые не узнала;
4. относит каждый квартал к зоне, в которую попадает его центр.

Вам остаётся посмотреть таблицу. Если код отнесён неверно — допишите поправку в анкете.

Зачем зоны: в производственных и общественно-деловых кварталах рабочие места дают и здания без точек сервисов (по правилам этажности и площади), в остальных — только здания с сервисами.

### Сервисы: как задать тип

Тип должен совпадать с одним из типов файла `таблица_групп_сервисов.csv` (открывается в Excel, столбец «тип»). Два способа:
- **папка** (или несколько папок, например «сервисы» и «промышленность»), где один файл — один тип, имя файла и есть тип: `school.geojson`, `cafe.geojson`, `works.geojson`;
- **один файл** с полем типа. Для выгрузки из OpenStreetMap — список полей тегов (`amenity`, `shop`, `office` …); соответствие тегов — в столбце «тег_OSM» таблицы групп.

Если в ваших данных есть тип, которого нет в таблице, программа покажет его в проверке. Добавьте строку в таблицу (тип и группу) или оставьте — тогда эти объекты не учитываются.

### Что особенно важно собрать

| Что | Почему | Что будет, если не собрать |
|---|---|---|
| **Этажность нежилых зданий** | от неё зависят поэтажная площадь и рабочие места | здание считается одноэтажным; одноэтажное здание производственной зоны без сервиса меньше 1 000 м² не даёт рабочих мест |
| **Точки производственных предприятий** (типы группы П: `works`, `metallurgy`, `engineering`, `food_industry` и др.) | в открытых данных заводы отмечены плохо | цех без точки считается по осторожной норме склада или отбрасывается |
| **Число мест школ и детских садов** | обеспеченность | подставляется наименьшая вместимость типа (школа 250, сад 80) |
| **Жители в зданиях** | все показатели жилья | считаются по жилой площади (30 м² на человека) |

Предприятие отмечается, если у него есть собственное производственное здание или площадка в границах города; офисы, магазины и шоурумы — нет. Источник и дату отметки запишите (например, «Яндекс Карты, рубрика „Производственное предприятие“, 18.11.2026»).

### Желательные

- **Метро и остановки** — как сервисы (типы есть в таблице групп); показываются справочно.
- **Файл OpenStreetMap региона** (`.osm.pbf`) — для точного расчёта обеспеченности школами и садами по пешеходному графу. Файл нужно положить в `data/osm/` или указать ссылку на него в анкете (раздел 4).

## 2. Что выписать из документов

| Что | Где взять |
|---|---|
| **Номера кварталов территории** | выберите в QGIS кварталы, которые меняют назначение; посмотрите поле номера |
| **Ограничения территории** (по желанию) | например, действующие предприятия и их санитарно-защитные зоны. Впишите в анкету текстом — он попадёт в вывод для вариантов с жильём |
| **Численность работников по статистике** (по желанию) | Росстат, территориальный орган статистики, сайт администрации: число и источник. Программа сравнит с ним расчёт рабочих мест |
| **КИТ** (коэффициент плотности застройки) | ПЗЗ или проект планировки. Если КИТ в ПЗЗ нет — строка таблицы Б.1 СП 42.13330.2016 по зоне, в которую переводится территория (например, «многоквартирная многоэтажная» — 1,2; «малой и средней этажности» — 0,8) |

## 3. Подготовка в QGIS (проверьте перед расчётом)

1. Все слои в одной системе координат (не EPSG:3857).
2. Контуры зданий с частями разной этажности разрезаны (например, многоэтажный административный корпус в общем контуре с одноэтажными цехами).
3. У жилых домов заполнен признак «жилое».
4. Точки предприятий лежат внутри контуров их зданий.
5. Слои лежат в папке `data/<имя города>/` рядом с ноутбуком.

## 4. Расчёт

1. Откройте ноутбук **`метод_сравнения_вариантов.ipynb`** (Anaconda, VS Code или Google Colab).
2. В ячейке **«Шаг 0. Ваши данные»** заполните анкету: пути к файлам, имена полей (как в QGIS: «Свойства слоя» → «Поля»), номера кварталов территории, КИТ и его источник. Зоны: путь к слою (или поле кварталов) и имя поля с кодом; коды программа распознает сама.
3. В ячейке выбора примера поставьте `ПРИМЕР = None`.
4. Выполните ячейки до **«Выгрузка JSON для конструктора»**. При `ИССЛЕДОВАНИЕ = False` можно нажать **Run All**: необязательные проверки пропускаются.
5. Ячейка **«Шаг 0б. Проверка данных»** покажет, что найдено, и подскажет, что исправить: доля зданий без этажности, типы сервисов не из таблицы, школы без мест, производственные кварталы без точек предприятий. Ошибки (✕) останавливают расчёт.
6. Если число жителей или рабочих мест на территории в варианте превышает 10 % от исходного числа по всему набору, программа показывает сравнение с городом целиком.
7. В `results/` появится `<код>_для_страницы.json` и таблицы кварталов и зданий. Для сравнения, карт и исследовательских проверок в ноутбуке включите `ИССЛЕДОВАНИЕ = True`. При `СЕМЬ_СЦЕНАРИЕВ = True` исследовательские таблицы покажут два эмпирических и пять экспериментальных сценариев. Оба набора всегда есть в готовом JSON.

В строке рабочих мест сначала указана сценарная оценка по кварталам-аналогам, в скобках — разница с исходной занятостью выбранной территории. В подробной таблице отдельно показана вместимость проектных помещений при полном использовании. Для расчёта по аналогам со старым файлом выгрузите JSON заново командой `python -m mixuse page configs/<код>.yaml` или из ноутбука.

**Точный расчёт школ и садов (по желанию).** В анкете поставьте `точный_расчёт=dict(включить=True, файл_OSM=…)`. В `файл_OSM` укажите путь к файлу региона OpenStreetMap (`.osm.pbf`) или ссылку на него (выгрузки по регионам — download.openstreetmap.fr, download.geofabrik.de); если оставить `None`, берутся файлы из папки `data/osm/`. Для точного расчёта нужна библиотека blocksnet в отдельном Python 3.11. Если её ещё нет, ноутбук остановится и подскажет, что делать: дважды щёлкните `подготовить_город.bat` в папке программы — он возьмёт настройки, которые ноутбук сохранил из анкеты (`configs\анкета_<код>.yaml`). Он ставит Python 3.11 и blocksnet (в `%USERPROFILE%\venvs\blocksnet311`), строит по файлу OpenStreetMap пешеходный граф и матрицу доступности, считает обеспеченность «как есть». Это занимает от пары минут для малого города до получаса и больше для крупного (Санкт-Петербург — около 25 минут и 5 ГБ памяти), выполняется один раз на город и заново — если изменились слои. Когда окружение с blocksnet есть, ноутбук сам готовит данные нового города и считает варианты через blocksnet. Без точного расчёта школы и сады считаются упрощённо — по местам в окружении.

### Эксперимент в конструкторе

1. Из корня проекта запустите локальный сервер. Оставьте окно командной строки открытым.

   ```powershell
   python -m http.server 8000 --bind 127.0.0.1 --directory страница
   ```

2. Откройте [конструктор](http://127.0.0.1:8000/конструктор.html). По умолчанию откроется Высоцк. Другой пример можно выбрать в списке городов. Если открываете HTML двойным щелчком, откройте файл города из `страница/данные/` кнопкой «Загрузить JSON». Интернет не требуется.
3. Выберите кварталы щелчками по карте, введите номера через запятую или нажмите «Территория из расчёта». Для примера выберите Высоцк и введите `305`.
4. В списке «Набор сценариев» выберите «2 эмпирических + 5 экспериментальных» для совместного сравнения. «Стандартный набор» сохраняет прежний режим. Задайте КИТ и радиусы `R` и `r` и нажмите «Рассчитать варианты». Доли согласованных семи сценариев фиксированы. В стандартном режиме доли можно менять.
5. Сравните результаты с «Как есть» в краткой и подробной таблицах. В разделе «Сопоставить два сценария» выберите два варианта. В скобках показано изменение относительно исходного состояния. «Доли вариантов» показывает состав застройки, а «Как программа считает» — формулы, единицы и источники применённых параметров.
6. Выберите сценарий для карты и нажмите «Территория и окружение», чтобы приблизить область расчёта. Значки К и ОД показывают приобретение и потерю доступа раздельно. Наведите курсор на квартал или значок для просмотра числа жителей. Под картой показано изменение жителей и рабочих мест для всей выбранной территории. Кнопки экспорта сохраняют CSV, GeoJSON и PNG.

В слое кварталов для QGIS поле `jobs` содержит исходную оценку. Поля `рабочие места <вариант>` и `изменение рабочих мест <вариант>` показывают итог и разницу для каждого квартала. Поля `занятость_К`, `занятость_ОД` и `занятость_П` с названием варианта дают разбивку по функциям. Оценка распределяется по площади выбранных кварталов, поскольку КИТ и доли функций общие для территории. Вне территории поля сценария повторяют исходную занятость, а изменение равно нулю.

Для своих данных загрузите `results/<код>_для_страницы.json`. Его сохраняет раздел «Выгрузка JSON для конструктора» или команда `python -m mixuse page configs/<код>.yaml`. Старые JSON можно открыть. Если нужны семь сценариев, исходная геометрия для экспорта или подробные источники параметров, которых в файле нет, выгрузите его заново.

**Петербургский пример — фрагмент.** В нём 1 490 из 9 368 кварталов в радиусе выгрузки 6,5 км. Это уменьшает размер файла и время расчёта в браузере. Численность и рабочие места всего набора, а также исходный расчёт BlocksNet, если он сохранён, берутся из полной подготовки. Итоговые эксперименты в `results/final_experiments/` рассчитаны по полным наборам. Карта, окружение, доступность и оценка школ и садов на странице учитывают только загруженные кварталы. У границы фрагмента могут отсутствовать доступные назначения. Для большего охвата увеличьте `ОХВАТ_JSON` в ноутбуке или `--clip` в команде `page`. Для полной выгрузки установите `ОХВАТ_JSON = None` или используйте `page` без `--clip`.

На странице обеспеченность школами и садами рассчитывается в оценочном или резервном режиме. Для расчёта семи сценариев средствами пакета используйте `python -m mixuse compare configs/vysotsk.yaml --territory 305 --paired`. При подготовленной матрице и доступном BlocksNet пакет выполняет точный расчёт. Без `--paired` действует стандартный набор из настроек.

### Доступ к К и ОД по пешеходной сети

1. **Подготовьте матрицу один раз для исходного слоя кварталов.** Для Высоцка и Гатчины файлы уже есть в `data/<код>/access/`. Для нового города заполните анкету ноутбука и поставьте `ПЕШКОМ = True` в шаге 0. Если подходящей матрицы нет, JSON будет использовать геометрическое расстояние. При выгрузке ноутбук покажет команду с путём к сохранённой анкете. Запустите её из корня проекта в окружении Python 3.11 с BlocksNet, например:

   ```powershell
   python -m mixuse access configs/анкета_мой_город.yaml --graph walk --osm-file data/osm/регион.osm.pbf
   ```

   Используйте путь к вашему файлу OpenStreetMap. С `--osm-file нет` граф загружается через Overpass. Команда сохраняет `matrix_walk.npz` и `matrix_walk.json`. Если слой кварталов изменился, подготовьте матрицу заново. Для чтения готовой матрицы BlocksNet не требуется.
2. **Сформируйте JSON.** Повторно выполните раздел «Выгрузка JSON для конструктора». `ПОРОГ_ХОДЬБЫ` по умолчанию равен 10 минутам, `МАКС_ПОРОГ_ХОДЬБЫ` — 20 минутам. JSON содержит направленные пары до максимума и их время. Для большого города в выгрузку входят только пары между кварталами выбранного фрагмента. Команда для готового YAML:

   ```powershell
   python -m mixuse page configs/vysotsk.yaml --walk-minutes 10 --walk-max-minutes 20
   ```

3. **Откройте файл кнопкой «Загрузить JSON».** В «Доступ к К и ОД» выберите «По пешеходной сети» и задайте порог до указанного максимума. Для большего порога заново выгрузите JSON с большим максимумом. При отсутствии подходящих связей конструктор сообщает об этом и использует геометрическое расстояние. `R` по-прежнему задаёт окружение в метрах. `r` остаётся геометрическим радиусом для близости к производству и для К/ОД в геометрическом режиме.
4. **Сравните и экспортируйте.** Включите семь сценариев. На карте можно показать изменения К, ОД или их сумму. CSV и GeoJSON сохраняют способ расчёта, а GeoJSON дополнительно содержит изменения по К и ОД раздельно. Для такого же выбора в Python используйте `python -m mixuse compare configs/vysotsk.yaml --paired --walk-minutes 10`. Порог применяется к времени от жилого квартала до каждого потенциального квартала назначения, включая каждый из выбранных кварталов территории.

## 5. Частые ошибки

| Сообщение или признак | Причина | Что сделать |
